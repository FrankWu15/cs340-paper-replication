### 关于 Once 与 atomic 两列

这两列偏差不是随机的，而是**呈现系统性镜像**：论文的 `atomic` 列与我们统计的
`sync.Once` 使用次数在 6/6 个仓库上都接近（Docker 15↔14、K8s 48↔45、etcd 13↔11、
CRDB 16↔13、gRPC 9↔9、BoltDB 1↔1，平均偏差约 8%），而论文的 `Once` 列比我们的
`sync.Once` 大 5~10 倍。

**排版错位可以排除**：pypdf 取得 Table 4 表头各词的 x 坐标依次为
363.9 / 387.3 / 412.1 / 431.4 / 469.7 / 491.7 / 512.1，与六行数据的各列
x 坐标逐一对齐（如 Docker 行 364.5 / 390.3 / 412.3 / 441.1 / 470.3 / 489.9 / 512.4）。
所以只可能是**论文统计脚本的归类与常规理解不同**（例如把 `sync.Once` 归到 atomic 列、
把另一类原语归到 Once 列）。本文没有原作者的脚本，无法判定具体规则，
因此 `Once` 与 `atomic` 两列标注为「不可比」，不作为复现结论的一部分。
`WaitGroup` 与 `Cond` 两列同样存在 1.5~3 倍差异，一并标注为不可比。

**Total 仍然可比**：各列的正负偏差在求和时相互抵消，Total 的偏差（多在 ±9% 内）
反而小于多数单列的偏差。
