# gRPC-C vs gRPC-Go 并发原语对照（论文 §3.2 末段）

论文要给一个"Go 的原语用得更多、更多样"的旁证：拿同门 C/C++ 实现 gRPC-C 做对照。
原文只给两个数——C 侧 **746** 个使用点、**5.3**/KLOC，Go 侧 **786** 个、**14.8**/KLOC、
**8 种**原语。没有给统计规则。本节的活是把这两个数各自钉到一个可复核的口径上。

## 1. 口径

| 项 | gRPC-C | gRPC-Go |
|---|---|---|
| 范围 | `src/core/` + `include/`（C core，不含 php/ruby 绑定） | 仓库全部 `.go` |
| 排除 | `third_party/` | `vendor/`、`*_test.go`（分子） |
| 计数对象 | `gpr_mu_lock` / `gpr_mu_unlock` / `gpr_mu_trylock` 调用点 | `lock_calls` + atomic + Once + WaitGroup + Cond + chan 收发 + Pool |
| 工具 | `count_primitives.py`（正则+行级声明剔除） | `tools/goast`（go/ast，与 Table 2/4 同一份） |

两侧都把"加锁"和"解锁"各算一次调用点，这是 Table 4 Mutex 列的口径（P2 阶段由
Docker 883、BoltDB 33 反推验证过），不是新发明。

## 2. 结果：746 精确命中

| gRPC-C 版本 | 锁使用点 | 核心原始行 | 核心代码行 | 每 KLOC（原始行） |
|---|---:|---:|---:|---:|
| v1.10.0 | 726 | 118.1K | 78.7K | 6.15 |
| **v1.11.0** | **746** | 134.5K | 88.8K | 5.55 |
| **v1.12.0** | **746** | 135.4K | 89.3K | 5.51 |
| v1.20.0 | 663 | 171.9K | 116.8K | 3.86 |
| 论文 | 746 | ≈140K | — | 5.3 |

746 是 `329 + 411 + 6`（lock / unlock / trylock），三个数分别可 grep 复核。
v1.11 与 v1.12 逐点相同，说明这个数在 2018 年上半年是稳定的；v1.10 差 20、
v1.20 掉到 663，是因为 2019 年 gRPC-C 把同步原语迁到 C++ 的 `Mutex`/`MutexLock` 抽象，
`gpr_mu_*` 调用被替换掉。

论文的 140K 与我们的 135.4K 差 3.4%，5.3 与 5.51 差 4.0%——两条都落在"同一个数"的范围内。
反过来说，这也确定了论文的 LOC 是**原始行**（含注释空行）：若按代码行只有 89.3K，
密度会是 8.35，与 5.3 差 57%。

## 3. 与 gRPC-Go 并排

| | 原语种类 | 使用点 | 代码行 | 每 KLOC |
|---|---:|---:|---:|---:|
| gRPC-C v1.12.0 | 1 | 746 | 89.3K | 8.35 |
| gRPC-Go `f6692351` | 7 列（8 类） | 771 | 32.1K（不含测试） | 24.0 |
| 论文 gRPC-C | 1 | 746 | 140K | 5.3 |
| 论文 gRPC-Go | 8 | 786 | 53.1K | 14.8 |

Go 侧的 771 与论文 786 差 1.9%，与 Table 4 里 gRPC-Go 那行（786 / 771，−1.9%）是同一个偏差，
来源是匿名函数与包装类型识别的边界，不是新问题。

"8 类"= `sync.Mutex`、`sync.RWMutex`、`sync.Once`、`sync.WaitGroup`、`sync.Cond`、
`sync.Pool`、`sync/atomic`、`chan`。Table 4 把 Mutex 与 RWMutex 并成一列，所以表里 7 列、
正文说 8 种。

## 4. 三处与论文对不上的地方

**① 两个密度的分母口径不同。** Go 的 14.8 = 786 / 53.1K，53.1K 是**含测试**的代码行；
C 的 5.3 = 746 / 140K，140K 是**原始行**。混着用会得出"密度差 2.79 倍"这种跨口径结论。
统一到"不含测试的代码行"：Go 24.0、C 8.35，比值 **2.88**；统一到"不含测试的原始行"：
Go 17.5、C 5.51，比值 **3.17**。两个都比论文的 2.79 高 3%~14%，量级一致但不精确——
论文没有公开 LOC 工具。

**② "only uses lock" 不严谨。** gRPC-C 有 80 处条件变量
（`gpr_cv_wait` 31、`gpr_cv_signal` 35、`gpr_cv_broadcast` 14），还有 `gpr_mu_init/destroy` 162 处。
成立的说法是"只有一种锁，没有 channel / atomic / Once / WaitGroup"。

**③ 论文没写版本。** 同一条口径在 v1.10 给 726、v1.20 给 663，只有 2018 年上半年的
v1.11/v1.12 给 746。复现时若随便挑一个 tag，这个数就复现不出来。

## 5. 结论

论文那句话的三层意思，两层站得住：

- **种类** 1 vs 8 —— 成立，且不依赖版本（C 侧只有 `gpr_mu` 一族）。
- **绝对数量** 746 vs 786 —— C 侧精确复现（v1.11/v1.12），Go 侧 −1.9%。
- **密度** 5.3 vs 14.8 —— 单个数只能靠论文那套混合分母才成立；换统一口径，比值落在 2.9~3.2 之间，
  方向与量级一致，但不能引用 2.8 这个具体倍数。
