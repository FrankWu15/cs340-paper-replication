## 0. 一句话

5 分钟讲完一项操作系统研究 + 2 分钟问答，四个人都要开口，PPT 或 PDF 必须带页码，全程英语。

---

## 1. 硬性约束

| 项 | 要求 | 不满足的后果 |
|---|---|---|
| 时长 | **5 min 演示 + 2 min Q&A**（每组共 7 min） | 超时挤掉结论段，直接压在 Presentation Efficiency（25%） |
| 载体 | PPT 或 PDF，**必须标页码** | Q&A 被追问「第几页那张图」时无法定位 |
| 参与 | **每个成员都要讲** | 未参与的学生该项**不计分**（no credit） |
| 语言 | 演示与问答均为英语 | — |
| 技术准备 | 提前验证 live demo、终端录屏、虚拟机示例；提前试 HDMI 与 U 盘 | 现场翻车按演示效率扣分 |

> 原文特意点出：操作系统论文常常要展示代码片段或架构图，**所有多媒体内容都要在演示前测过**。

---

## 2. 五分钟结构

| 时间 | 段落 | 必须回答的问题 | 主要评分项 |
|---:|---|---|---|
| 1:00 | 引言与问题陈述 | 这是哪一个具体的 OS 挑战？瓶颈 / 可靠性 / 安全漏洞在哪？论文的核心论点是什么？ | Systems Context 10% |
| 1:00 | 技术方法与研究路径 | 架构或框架长什么样（放图）？数据怎么来（kernel instrumentation / tracing / benchmark）？为什么这样设计而不是别的？ | Technical Accuracy 25% |
| 1:30 | 主要发现与结果 | 量化结果（吞吐、延迟、开销）？与基线怎么比？这会怎样改变系统的构建或调优方式？**必须用图表** | Technical Accuracy 25% |
| 1:00 | 批判性分析与局限 | 生产规模还成立吗？硬件 / 内核版本 / 遗留软件能不能集成？安全影响？别人能不能复现？ | Analytical Depth 25% |
| 0:30 | 结论与影响 | 一句话 takeaway；与当前 OS 设计或新兴硬件趋势的联系 | Systems Context 10% |

时间账：1 + 1 + 1.5 + 1 + 0.5 = 5 分钟。**结果段最长**，因为它同时吃 Technical Accuracy 和演示说服力。

---

## 3. 评分标准

| 标准 | 占比 | 拿分要点 |
|---|---:|---|
| 技术准确性 Technical Accuracy | **25%** | OS 概念用对、架构讲准、术语恰当（不要混用 process/thread、mutex/semaphore 这类） |
| 分析深度 Analytical Depth | **25%** | 批判性评估工程权衡；评价实证方法在系统语境下是否站得住；对局限有真思考，不是念免责声明 |
| 演示效率 Presentation Efficiency | **25%** | 守住 5 分钟；5 分钟内有学术演示的逻辑流；图有效（架构图、性能图）；**主次分明** |
| 问答能力 Q&A Competence | **15%** | 答得准；压力下能解释技术细节；能接住追问并互动 |
| 系统背景 Systems Context | **10%** | 讲清对现代 OS 的实际意义、与行业趋势的联系、实现可行性 |

**25 / 25 / 25 三分天下**——内容和表达同权。凡把 5 分钟全用来堆结果、不留批判性分析的，等于主动放弃 25%。

## 4. 逐段要求展开

### 4.1 引言与问题陈述（1 min）

三件事必须齐：**系统背景**（哪个 OS 挑战）→ **具体动机**（性能瓶颈 / 可靠性问题 / 安全漏洞）→ **论点陈述**（论文对 OS 的核心贡献）。

不要用「本文提出了一种新方法」开头，要直接给矛盾和代价。

### 4.2 技术方法与研究路径（1 min）

- **系统架构 / 框架设计**：必须有图。架构图、系统调用流程、实验工作流都算。
- **数据收集方式**：说明是内核插桩、追踪与性能分析，还是基准测试套件——这决定结果的可信边界。
- **关键工程决策**：为什么选这个架构而不是另一个。这一条是 Analytical Depth 的提前落点。

### 4.3 主要发现与结果（1.5 min）

- 量化结果要落到系统工程关心的量：吞吐量、延迟、开销降低。
- 必须有**与基线的对比**，单独一个绝对数字没有意义。
- 必须回答「实际意义」：这会怎样改变 OS 的构建或调优方式。
- **图表优先**于文字罗列。

### 4.4 批判性分析与局限（1 min）

原文列了四个必答方向，缺一个就少一块分：

1. **可扩展性隐忧**：多核、高负载、生产规模下是否仍然有效？
2. **兼容性**：硬件架构、内核版本、遗留软件的集成代价。
3. **安全影响**：所提方法引入的攻击面或防护缺口。
4. **可复现性**：其他系统研究者能否轻松实现？

这一节不是「本研究有局限性」一句话带过，要给出**具体条件**：在什么配置下会失效、失效后表现是什么。

### 4.5 结论与影响（0.5 min）

- **一句话 takeaway**，给系统从业者的。
- 与当前 OS 设计或新兴硬件趋势（如新互连、异构核、持久内存）的联系。

## 5. 学术诚信

课程对本项有四条明确限制：

1. 直接引用论文的内容**尽量减少**，且**注明出处**。
2. **所有架构解读与分析必须是自己的**。
3. **禁止未经批判性评估就使用生成式内容**（generated content）。用了生成内容必须有评估痕迹。
4. 凡用于理解技术背景的**外部资源均须引用**。

落地建议：图自己重画并标「adapted from [x]」；引用的数字标页码或表号；用 AI 辅助生成的讲稿/图，要在备注里写清哪部分、怎么核过的。
